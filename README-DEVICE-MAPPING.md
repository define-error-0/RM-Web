# 设备固件管理系统说明

## 概述

本系统按**固件类型 + 设备型号**的层级结构组织固件文件。系统支持两种加载模式：

1. **自动模式** - 已连接设备时，自动识别设备型号并加载对应固件
2. **手动模式** - 未连接设备时，用户选择设备类型，系统列出该类型的所有固件

两种模式都能避免用户选择错误的固件导致设备变砖，用户只需要选择固件版本即可。

## 文件夹结构

```
bin/
├── ctl/                    # 遥控器控制器固件
│   ├── MT8/               # RadioMaster MT8 的固件
│   │   ├── MT8-v1.9.2.bin
│   │   ├── MT8-v1.9.1.bin
│   │   └── MT8.bin
│   ├── MT6/               # RadioMaster MT6 的固件
│   │   └── MT6-v1.0.0.bin
│   └── T8L/               # RadioMaster T8L 的固件
│       ├── T8L-v1.2.0.bin
│       └── T8L.bin
├── radio/                 # 遥控器内部高频头固件（暂时关闭）
│   └── firmware3.6.0.bin
├── sensor/                # 传感器固件
│   └── RM_ERS_Sensor-v1.4.bin
└── files.json            # 自动生成的配置文件
```

## 固件类型说明

### 1. ctl - 遥控器控制器固件
用于更新遥控器主控制器的固件。不同型号的遥控器（MT8、MT6、T8L等）有各自的固件。

### 2. radio - 高频头固件
用于更新遥控器内部高频头模块的固件。**该功能目前暂时关闭。**

### 3. sensor - 传感器固件
用于更新各类传感器的固件。

## 工作原理

### 自动模式（推荐）

**适用场景：** 已连接设备

1. **连接设备** - 系统获取设备名称（如 `RadioMaster MT8`）
2. **自动查找配置** - 从 `bin/files.json` 查找该设备的固件配置
3. **自动定位文件夹** - 根据配置自动定位到正确的文件夹（如 `bin/ctl/MT8/`）
4. **加载固件列表** - 列出该文件夹中所有可用的固件版本
5. **用户选择版本** - 用户只需从列表中选择要刷入的版本

**优势：**
- ✅ 完全自动识别，无需手动选择设备类型
- ✅ 零出错风险，系统确保只加载匹配的固件
- ✅ 最简单的用户体验

### 手动模式

**适用场景：** 未连接设备，或需要为其他设备准备固件

1. **选择设备类型** - 用户从下拉框选择（遥控器/高频头/传感器）
2. **查找该类型设备** - 系统列出该类型的所有设备型号
3. **选择设备型号** - 如果有多个型号，用户选择具体型号
4. **加载固件列表** - 列出该设备所有可用的固件版本
5. **用户选择版本** - 用户选择要刷入的版本

**优势：**
- ✅ 无需连接设备即可浏览固件
- ✅ 可以为其他设备准备固件
- ✅ 仍然限制在正确的固件类型内，防止误选

### 安全机制

- ✅ **自动识别设备型号**，避免选错固件类型
- ✅ **自动定位正确文件夹**，不会加载其他型号的固件
- ✅ **用户只选择版本**，不需要手动选择设备类型
- ✅ **防止变砖**，系统确保只加载匹配的固件

## 添加新设备

### 情况 1：为现有设备添加新版本

直接将新的固件文件放入对应的设备文件夹，然后重新运行 `generate-files-json.bat`。

**示例：为 MT8 添加新版本**
```
bin/ctl/MT8/MT8-v2.0.0.bin  # 新增文件
```

运行 BAT 脚本后，JSON 会自动更新。

### 情况 2：添加全新设备型号

**步骤 1：创建设备文件夹**

根据设备类型，在对应的文件夹下创建设备型号文件夹：
```
bin/ctl/MT9/               # 新增 MT9 遥控器
bin/sensor/NewSensor/      # 新增传感器
```

**步骤 2：放置固件文件**
```
bin/ctl/MT9/MT9-v1.0.0.bin
bin/ctl/MT9/MT9-v1.0.1.bin
```

**步骤 3：修改 BAT 脚本**

编辑 `generate-files-json.bat`，添加设备配置：

```batch
:: RadioMaster T8L -> ctl/T8L
set /a deviceCount+=1
set "device[3].name=RadioMaster T8L"
set "device[3].type=ctl"
set "device[3].model=T8L"

:: 添加新设备 MT9
set /a deviceCount+=1
set "device[4].name=RadioMaster MT9"
set "device[4].type=ctl"
set "device[4].model=MT9"
```

**配置说明：**
- `name`: 设备完整名称，必须与 `window._deviceInfo.devName` 完全一致
- `type`: 固件类型（`ctl` / `radio` / `sensor`）
- `model`: 设备型号，对应文件夹名称

**步骤 4：生成配置文件**

双击运行 `generate-files-json.bat`，脚本会：
1. 扫描配置的设备文件夹
2. 列出每个文件夹中的所有 `.bin` 文件
3. 生成 `bin/files.json`
4. 显示当前文件结构

## JSON 文件结构

生成的 `bin/files.json` 格式：

```json
{
  "devices": {
    "RadioMaster MT8": {
      "type": "ctl",
      "model": "MT8",
      "files": [
        "MT8-v1.9.2.bin",
        "MT8-v1.9.1.bin",
        "MT8.bin"
      ]
    },
    "RadioMaster MT6": {
      "type": "ctl",
      "model": "MT6",
      "files": [
        "MT6-v1.0.0.bin"
      ]
    },
    "RadioMaster T8L": {
      "type": "ctl",
      "model": "T8L",
      "files": [
        "T8L-v1.2.0.bin",
        "T8L.bin"
      ]
    }
  }
}
```

**结构说明：**
- `devices` - 所有设备的配置
  - `设备名称` - 完整的设备名称
    - `type` - 固件类型（ctl/radio/sensor）
    - `model` - 设备型号（对应文件夹名）
    - `files` - 该设备可用的固件文件列表

## 使用流程

### 自动模式（已连接设备）

1. **连接设备** - 通过串口或蓝牙连接设备
2. **点击"从服务器加载固件"** - 系统自动识别设备并加载对应固件列表
3. **选择固件版本** - 如果有多个版本，从下拉列表中选择
4. **更新固件** - 点击"确认更新"按钮完成固件更新

### 手动模式（未连接设备）

1. **选择设备类型** - 从下拉框选择"遥控器"、"高频头"或"传感器"
2. **点击"从服务器加载固件"** - 系统列出该类型的所有设备
3. **选择设备型号** - 如果有多个型号，选择目标设备
4. **选择固件版本** - 如果有多个版本，选择要使用的版本
5. **更新固件** - 连接设备后，点击"确认更新"完成固件更新

## 故障排除

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 提示"请先连接设备" | 设备未连接或未识别 | 确保设备已正确连接并识别 |
| 提示"未找到设备的固件配置" | JSON 中没有该设备 | 检查设备名称是否与 BAT 配置一致 |
| 文件加载失败 | 文件路径错误 | 确认文件在 `bin/type/model/` 中 |
| BAT 脚本警告 | 文件夹不存在或为空 | 先创建文件夹并放入固件文件 |
| 加载了错误的固件 | 设备名称配置错误 | 检查 BAT 中 `name` 是否与实际一致 |

## 注意事项

1. **设备名称必须精确匹配** - `window._deviceInfo.devName` 返回的值必须与 BAT 配置的 `name` 完全一致（区分大小写）
2. **文件夹结构必须正确** - 固件文件必须放在 `bin/<type>/<model>/` 目录下
3. **固件类型不能混淆** - ctl、radio、sensor 各有用途，不可混用
4. **运行 BAT 重新生成 JSON** - 每次添加或修改固件文件后，都要运行 BAT 脚本更新 JSON
5. **固件文件名建议包含版本号** - 方便用户识别（如 `MT8-v1.9.2.bin`）
6. **不要手动修改 JSON** - 手动修改会被 BAT 脚本覆盖，应该修改 BAT 配置

## 优势

1. ✅ **三层结构清晰** - 固件类型 → 设备型号 → 版本文件
2. ✅ **防止误操作** - 自动识别设备，避免选错固件类型导致变砖
3. ✅ **支持多版本** - 同一设备可以存放多个固件版本
4. ✅ **易于维护** - 按设备型号组织，便于管理
5. ✅ **易于扩展** - 添加新设备只需修改 BAT 配置
6. ✅ **用户友好** - 用户只需选择版本，无需了解固件类型
